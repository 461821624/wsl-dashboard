# Docker 管理

在侧栏打开 Docker 页面，选择环境后查看容器，或启动、停止、重启容器、查看最近 200 行日志。停止和重启会中断容器中的服务。列表包含正在运行和已停止的容器；操作完成后会刷新，外部变更需要手动刷新。

页面使用紧凑卡片，镜像和端口默认单行省略，点击“详情”可查看并复制完整名称、ID、镜像和端口。搜索匹配名称或镜像（忽略大小写及首尾空白），支持全部、运行中、已停止筛选；筛选不会触发 Docker 命令。“已停止”对应 `exited`，其他状态仍可在“全部容器”中查看。

日志在独立弹窗中展示，等宽字体、默认不换行，支持横向滚动、刷新、复制和 Esc 关闭；读取失败会保留原日志并显示错误。文本框配色随应用深浅色主题同步。容器操作在对应卡片上显示进度，结束后提示结果；操作期间暂时禁用其他 Docker 请求。复制操作复用项目现有的 Windows 剪贴板工具。

## 扩展功能

左侧 Docker 为可展开菜单，下面分别进入“容器、镜像、Compose”。右侧只显示所选页面，不再放横向功能切换按钮。窄侧栏点击 Docker 会展开侧栏；主导航过长时可以滚动，底部捐赠、设置和关于保留原位置。

- **镜像**：切换到“镜像”页签查看本地镜像、完整 ID、全部标签、大小、创建时间和容器引用数，支持搜索和复制详情。相同 ID 的多个标签合并展示，大小不能简单累加为磁盘实际占用。引用数通过容器的不可变镜像 ID 查询，包含已停止容器，避免标签移动后误判。输入镜像名或仓库地址并点击“拉取”时才联网，使用当前 CLI 已有认证；不增加仓库密码输入或保存。
- **多个自定义拉取源**：镜像页提供源下拉框，可逐个添加域名、端口及仓库前缀，例如 `mirror.example.com`、`localhost:5000/cache`，也可粘贴带 `https://` 的地址。点击“添加并使用”后保存并选中；重复添加同一规范化地址只选中已有项。可切换已有源或移除当前源，移除当前源后回到“Docker 默认”。地址列表和当前选择保存在用户的 `~/.wsldashboard/settings.toml` 中，字段为 `docker-pull-sources` 和 `docker-pull-source`；切换 Desktop、WSL、root 或重启应用后仍保留。
- **源的作用范围**：未配置时默认使用“Docker 默认”，保留原始拉取参数，沿用引擎已有配置（不会移除用户原先的引擎加速源）。自定义源仅重写本工具拉取的 Docker Hub 镜像，例如 `nginx:latest` 转为 `mirror.example.com/library/nginx:latest`，`team/app:v1` 转为 `mirror.example.com/team/app:v1`；`docker.io` 和 `index.docker.io` 前缀也会识别。已明确指定 `ghcr.io`、私有仓库域名或 `localhost:端口` 的镜像仍走原地址。拉取前显示实际目标参数，失败不自动切源或重试官方源。配置地址的服务必须支持这种前缀拉取方式，不是任意 HTTP 代理地址。
- **镜像名称与引擎配置**：拉取后的镜像保留自定义源前缀，不自动重新打标签；终端和 Compose 不会读取本工具的源偏好。本工具不修改 `daemon.json`、Docker Desktop 配置或 TLS 设置，也不重启 Docker。地址不接受 `http://`、账号密码、查询参数或片段；私有源认证沿用当前用户的 Docker CLI 配置。
- **删除镜像**：有容器引用时禁用删除按钮；执行前再次查询当前引擎，并弹窗确认。不使用 `--force`，不删除容器、数据卷或执行全局清理。多个标签等 Docker 冲突会直接显示错误，需要先在终端处理相应标签。操作失败后点击刷新再重试。
- **Compose**：按容器的 `com.docker.compose.project` 标签发现已有项目，包含已停止项目；详情列出服务、状态和容器名。支持批量启动、确认后批量停止、按容器分组查看日志。不需要 Compose 插件或原 YAML 文件；它管理现有容器，不执行 `compose up/down`，不重建服务、不恢复依赖启动顺序、不重新执行健康依赖条件，也不会删除数据卷。已经 `down` 且无剩余容器的项目无法发现。批量操作失败可能已有部分容器完成操作，列表会重新查询；请核对状态后重试。
- **监控**：运行中容器展开“详情”后可打开“资源监控”，显示 CPU、内存使用量与上限、内存占比、累计网络收发、累计磁盘 I/O 和 PIDs；这些数字来自 `docker stats --no-stream`，网络和磁盘数据不是每秒速率。不保存监控历史。
- **日志与监控自动刷新**：弹窗支持勾选自动刷新；监控默认开启，日志默认关闭。每次请求完成后间隔 3 秒再请求，始终最多一个 Docker 请求；关闭弹窗、离开 Docker 页面或发生错误后不再自动请求。日志每次替换为最近 200 行快照，项目按容器分组，不跨容器按时间合并；不是 `logs --follow` 流式订阅，高频日志可能在两次快照间被覆盖。保留 stdout/stderr，但不保证两者的合并时间顺序。

## 环境要求

- **Docker Desktop**：Windows 能通过 PATH 找到 `docker.exe`，Desktop 已启动并处于 Linux 容器模式。页面显式使用 `desktop-linux` context，不切换全局 context。
- **WSL Docker Engine**：发行版为 WSL 2，已安装 Docker CLI，本地 Engine 已启动。默认使用发行版默认用户连接 `/var/run/docker.sock`；权限不足时，可在页面勾选“以 root 用户访问 Docker”，工具将通过 `wsl --user root` 执行查询、容器启停和日志读取，不需要手动修改用户组或 socket 权限。
- root 访问默认关闭，仅对当前选中的 WSL 环境有效，切换环境或重启应用后恢复关闭。开启时会明确显示 root 权限提示；切换身份会清空旧数据并重新检测，操作进行中不能切换身份。
- 发行版列表来自仪表板现有实例列表，刷新 Docker 页面会同步可选发行版；内部 `docker-desktop*` 发行版不作为普通 Engine 目标。
- 选择 WSL 环境会执行发行版内的命令，可能启动原本停止的发行版。Docker Desktop 的 WSL 集成也可能让多个入口连接同一个引擎，这些入口中的容器并非独立副本。

## 实现范围

复用现有侧栏、Slint 控件、Tokio 后台任务和国际化机制，新增独立 Docker 命令模块、UI handler 和页面。保留原有页面编号，Docker 使用编号 9；自定义拉取源复用现有用户配置保存，不新增依赖。

命令通过参数数组执行，不经过 shell。Desktop 固定指定 context；WSL 固定本地 socket，并清除 Docker 连接环境变量。容器列表使用 `docker ps --all --no-trunc --format` 输出逐行 JSON，仅接受完整容器 ID 和允许的操作；项目和服务标签使用 `.Label` 按键单独取值并经过 JSON 编码，避免拆分普通标签字符串造成歧义。

切换目标会清空旧环境的列表及日志；执行期间禁用目标切换和重复操作，防止结果与目标不一致。普通后台命令限时 45 秒，镜像拉取限时 10 分钟；每个输出流最多读取 1 MiB，项目日志合计最多 1 MiB，超限时明确报错而非展示不完整的列表。超时会结束宿主 CLI 进程，WSL 内或引擎侧操作可能继续，需刷新确认状态后再重试。拉取期间暂时不能切换环境或执行其他 Docker 操作。

普通刷新保留搜索、筛选、展开项及列表滚动位置，数据减少时滚动位置会受剩余内容高度限制。刷新失败时保留上次结果并显示错误，此时不能操作旧数据，需要先刷新成功。切换环境或 root 身份时清空列表、搜索、展开项、滚动位置和日志。

暂不包含 rootless 或自定义 socket、远程 context、Windows 容器、Compose YAML 编辑或导入、自动安装、删除容器、数据卷清理和无遗漏的流式日志订阅。

## 验证

自动检查：`cargo test --locked docker::`、`cargo test --locked config::models::docker_pull_source_tests` 和 `cargo check --locked`。Docker 模块共 13 项测试，覆盖容器 JSON、无效输出、ID/操作校验、目标参数隔离、搜索与状态筛选、输出上限、镜像标签合并、镜像参数校验、项目精确匹配、监控输出、自定义源地址校验及 Docker Hub 地址转换；另有 2 项配置测试验证旧配置默认无自定义源、多地址与当前选择的 TOML 往返。这些测试不会连接真实 Docker 或改变容器状态。完整 GUI 测试构建的内存占用较高；本次模块测试使用独立 rustc 测试入口加载同一生产模块，仅用翻译键替代翻译加载，配置测试加载实际配置模型，整应用通过 Cargo 编译检查，未运行完整 GUI 测试套件。

人工验收（在测试容器上执行）：

1. 访问其他页面时不应触发 Docker 检测；首次进入 Docker 页面检测 Desktop。
2. Desktop Linux 引擎启动时展示容器；未安装 CLI、引擎停止或权限不足时显示错误。
3. 选择安装有 Engine 的 WSL 2 发行版，核对列表与该发行版终端内的 `docker ps -a` 一致。
4. 启动、停止、重启测试容器后核对状态；日志应包含 stdout 与 stderr，且支持选择复制。
5. 切换环境时旧列表和日志消失，执行中不能切换或重复操作；空环境应显示空状态。
6. CLI 当前 context 指向其他引擎时，页面仍应操作指定的 Desktop 或 WSL 本地引擎。
7. 默认用户无 socket 权限时，勾选 root 访问后应能连接已运行的本地引擎；取消勾选后重新以默认用户检测。切换环境时开关恢复关闭，Docker Desktop 不显示此选项。
8. 检查搜索与状态筛选组合、无匹配提示、展开后完整信息及复制结果；普通刷新保持展开项与滚动位置，切换环境则重置。
9. 打开日志弹窗并刷新、复制、关闭；长日志保持不换行并可水平滚动，关闭后列表恢复完整高度，读取错误不清空旧日志。
10. 在测试环境拉取镜像，检查同 ID 多标签合并、已停止容器的引用数、删除确认及被引用镜像的删除限制；取消删除不应发送删除命令。
11. 用包含两个服务的测试 Compose 项目检查项目发现、运行数、服务详情、批量启停、停止确认及项目日志；核对数据卷和容器均保留。
12. 检查监控与终端 `docker stats --no-stream` 一致；切换自动刷新、关闭弹窗、离开页面和模拟引擎断开，确认停止定时请求。日志自动刷新应保留弹窗而不挤压列表。
13. 添加两个自定义源，检查下拉选择、重复添加、移除当前源恢复默认、重启后列表与选择保留；空配置应默认选中 Docker 默认。添加无效地址或保存失败时不应改变当前生效源。
14. 输入 Hub 短名、带组织名的镜像、摘要及显式第三方仓库地址，核对目标预览。用测试源实测一次拉取，检查实际镜像名保留源前缀；失败后不应自动向其他源发出请求。
